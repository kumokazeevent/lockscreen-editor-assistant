# 0.14.3 · 后台右侧预览图批量保存

日期：2026-10-05（Asia/Shanghai）

## 目标

列表提示“请添加图片”但编辑页右侧仍显示图片时，在列表页批量取得这些图片并保存本地，供用户手动上传。

## 主要变更

- 新增 `backend-preview.js`：验证详情 ID，只读取 `originImageWebp.url`，生成包含编号、ID、标题的文件名。
- `content.js`：通过当前登录会话 GET `/api/OverseasLockScreen/get?id=...`。
- `assistant.js`、`assistant.css`：读取／下载／停止、逐条状态及进度、多标签隔离；独立于文案处理批次。
- `background.js`、`background-downloads.js`：4 路下载、30/40 分组、文件头识别、格式转换和浏览器完成确认。
- `manifest.json`、`background-entry.js`：新增模块载入，升级至 0.14.3。
- 新增 `tests/backend-preview-logic.mjs`、`tests/backend-preview-ui.mjs`；同步载入和静态检查。

## 问题与选择

1. 列表与左侧上传框依赖 `originImage`，右侧预览依赖 `originImageWebp`。直接取列表图片会漏掉目标；直接找正文图片则会取错。使用详情接口按 ID 精确取右侧字段。
2. 字段名含 Webp，但 URL 后缀也可能是 JPEG；真实样本甚至声明 JPEG 而文件内容是 WebP。识别文件头再决定是否转码，避免伪 JPG。
3. 图库去重会跳过两个条目共用的图片，但人工重新上传需要每条对应的文件。此功能单独保存，保持编号与 ID，不写图库用量记录。
4. 下载时固定目标目录，避免用户切换文件夹后发生路径错位。浏览器确认完成才显示“已保存”。

## 验证

八项静态／逻辑／MV3／浏览器测试通过，新增用例覆盖缺图、错配 ID、重复素材的逐条保存、30/40 分组、AVIF/PNG/JPEG、错标 WebP、失效链接、下载中断、重试和停止。

实站以 GET 读取详情，并用正式转码函数验证一张真实 WebP 转成同尺寸 JPEG；没有向后台上传或保存。整批真实下载和手动上传待用户使用时验收。
