# ADR 0002：使用原生 JavaScript 与浏览器 API

状态：已实施；历史决策日期待确认。

## 上下文

项目包含页面内容脚本、主世界桥、设置页和悬浮窗，当前没有 `package.json` 或编译步骤。代码使用 `fetch`、DOM API、`chrome.storage` 与 `chrome.downloads`。

## 考虑的选项

1. 原生 JavaScript、`fetch` 和 DOM：文件可直接被扩展加载，无打包依赖；但大文件容易变得难维护，需手工管理注入顺序。
2. React/Vue + 打包器、axios 等依赖：组件化与开发工具更成熟；但需要构建链、依赖管理和产物同步，增加交接复杂度。

## 决策

目前继续以原生 JS/HTML/CSS 构建；内容脚本按 manifest 顺序加载，后台以原生模块入口组合，网络请求使用 `fetch`。

## 原因

原因待确认：由前代 Agent 决策。现有代码已经围绕扩展权限和目标站点 DOM 展开，直接加载可以减少安装/构建环节。原生 `fetch` 便于配合 `AbortController`、响应头和超时诊断；没有明确证据表明引入 axios 或前端框架能消除当前的主要适配风险。

## 影响

- 正面：无需安装依赖即可加载和静态校验；运行时代码与源码一致。
- 负面：`assistant.js`、`background.js` 体量较大；若继续扩展功能，应考虑增量拆分并补测试，不能只为换技术栈而重写核心逻辑。
