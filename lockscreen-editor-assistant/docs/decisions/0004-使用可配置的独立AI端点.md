# ADR 0004：使用可配置的独立 AI 端点

状态：已实施；历史决策日期待确认。

## 上下文

用户需使用自己购买的模型、API Key 和端点，且部分兼容服务商对模型名、思考字段、token 参数和错误格式存在差异。

## 考虑的选项

1. 可配置的 Chat Completions 兼容端点、模型与 Bearer Key：用户能选择服务商，主 AI 与可选审核 AI 分开配置；代价是必须兼容多种响应和错误形态。
2. 固定绑定单一服务商与模型：实现、排错更简单；但无法使用用户指定的模型，提供商故障时无切换余地。
3. 完全本地改写：无外部 API 成本；但 `workflow.js` 的本地模式只做词语候选，缺少语义理解。

## 决策

设置页保留用户可改的 AI 端点、模型、Key、可选备用模型和可选第二审核 AI；请求以 Chat Completions 风格 JSON 发送。默认 DeepSeek 官方端点仅为初始地址，不强制模型名。可切换本地模式，但结果需人工复核。

## 原因

用户需求和代码一致：`options.js` 将模型默认留空，`background.js` 按填写值发请求；端点只对已知 DeepSeek/OpenCode 路径做必要规范化。面对不同提供商，错误分类、token 字段回退和 `finish_reason=length` 扩容比静默替换模型更易诊断。历史上每项兼容分支的具体引入原因待确认：由前代 Agent 决策。

## 影响

- 正面：支持独立付费账户、模型选择与可选审核；诊断不应保存请求头/API Key。
- 负面：服务商并非完全兼容，真实网络可能出现 401、404、空响应或超时；扩展也无法保证模型一定遵守词数和语言约束。
