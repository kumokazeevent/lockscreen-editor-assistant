# 正文直读和文案链

日期：待确认。对应既有文档的 0.14.1—0.14.2 节点。

## 目标

优先真正读取文章正文并生成简介，再依据生成的简介浓缩标题；避免错位原文和版权页脚污染结果，同时减少额外请求。

## 主要变更

- `page-bridge.js`：在页面主世界观察已有 fetch/XHR JSON，按内容 ID 捕获最多 12,000 字符的正文、标题、简介与地址。
- `content.js`：把捕获记录与列表卡片按 ID 匹配，并传给批次扫描结果。
- `assistant.js`：保存正文、记录来源，必要时依次退回文章页、原简介、原标题；旧结果缺少来源标记或无效正文时重做文案。
- `background.js`、`workflow.js`：以“正文→原简介→原标题”为简介来源，标题依据生成简介；0.14.2 主 AI 正常情形用一次请求完成，原标题另用于搜图词。
- `tests/validate-extension.mjs`、`tests/background-logic.mjs` 等：校验来源链、MV3 加载和模拟流程。

## 遇到的问题

- 早期抓取落地页可能只读到版权和联系信息，导致标题简介偏题；当前会拒绝短版权页脚，并优先使用后台列表已有正文。
- 真实后台是否始终返回 `content`、正文清洗是否足够以及错位记录的匹配可靠性仍需在目标页面人工验收。
